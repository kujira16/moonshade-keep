# Codex への指示書（第4弾）：DS並みの解像度で、キャラ・敵・背景を 32×32 に作り直す

画面の解像度を DS 並みに上げました。**ゲーム内部の描画は 320×288（今までの縦横 2 倍）**です。
これに合わせて、すべての絵を **今の 2 倍の細かさ（主人公は 32×32）** で作り直してください。

共通のルール（API キーの扱い、候補を作って採点する仕組み、`assets/source/` → `polish_sprites.py` → `assets/` の流れ、ブランチに push して PR を作る）は、前回までの指示書（`docs/CODEX_SPRITES_HQ.md`、`docs/CODEX_KNIGHT_V3.md`）と同じです。

- 参照画像：`docs/reference/knight.png`
- 16×16 の配置図（目標の参考）：`docs/reference/knight_16_template.png`

---

## 0. ゲーム側の仕組み（もう入っているもの）

- ゲームの計算（移動、当たり判定、ステージの地図）は今まで通り **160×144・8px タイル** のまま。
- 描画だけが `assets/overrides.json` の **`"renderScale": 2`** で 2 倍の細かさになっている。
- 高解像度の絵は、`overrides.json` に **`"名前": { "w": 1フレームの横幅(画像px), "scale": 2 }`** と書く。
  例：`"player_idle": { "w": 32, "scale": 2 }` → 32×32 の画像が、ゲーム上の 16×16 の枠にぴったり描かれる。
- 今まで通り数字だけ（`"skeleton": 16`）で書いた絵は、等倍（scale 1）として扱われる。つまり**作り直していない絵もそのまま動く**ので、少しずつ置き換えてよい。
- 背景タイル（`t_brick` など）は、**32×32 の画像（scale 2）を「ゲーム上 16×16＝タイル 2×2 マス分の模様」**として描く仕組みが入っている（`js/game.js` の `drawTile`）。

## 2. 主人公の作り方（第3弾の流れを 2 倍にする）

```
gpt-image（images.edit、参照に knight.png）
  → フルカラーの 64×64 ドット絵（1024×1024、1 マス = 16px）
  → マス目読み取り → 色相で部位を判定 → 64×64 の部位マップ
  → 部位の優先順位つきで 32×32 に縮小（第3弾と同じ優先順位）
  → 部位 → パレット番号 → assets/source/<名前>.png（32×32）
  → polish_sprites.py → assets/<名前>.png
```

- 第3弾では 32×32 で生成して 16×16 に縮めていた。今回は **64×64 で生成して 32×32 に縮める**。目・アホ毛・ベルトなど細い部分が、優先順位つきの縮小で残る。
- 32×32 なら、16×16 では無理だった次のものを**必ず描く**（採点の必須条件に追加する）。
  1. 目：一番暗い色の 2×3 前後に、一番明るい色のハイライト 1 ドット
  2. アホ毛：頭のてっぺんから 3〜4 ドット、カーブして立つ
  3. 横の編み込み：髪の後ろ側に、明るい色と暗い色が交互の 2〜3 段
  4. 丸い肩当て：直径 5〜6 ドット、明るい色＋一番明るいハイライト
  5. 胸当ての模様：明るい色の上に暗い色の線 2〜3 本
  6. 青い服と鎖かたびら：暗い色の上に、明るい色の点を市松に
  7. ベルトとバックル、腰の剣（つばは一番明るい色）
- 採点で使う目標の配置図は、`knight_16_template.png` を 2 倍に拡大したものを「大まかな配置」として使う（部位の位置が合っているかだけを見る。細部は上の必須条件で見る）。
- 歩き4コマは、立ち絵を参照にして作り、**頭の部分（上から 14 行）を立ち絵とそろえる**。

## 3. 敵・ボス・アイテム・背景

- 主人公と同じく **フルカラーで 2 倍の大きさ（64×64 など）に生成 → 色相で部位判定 → 優先順位つきで半分に縮小** の流れにする。
  - ガイコツ：骨＝一番明るい、影＝明るい、目の穴と関節＝一番暗い。あばら骨が 3 本見えること。
  - コウモリ：体＝暗い、翼の骨＝明るい、目＝一番明るい 1 ドット。
  - ゴースト：体＝一番明るい、すそ＝明るい、目と口＝一番暗い。
  - ボスの頭：角のある頭蓋骨。目の穴の奥に一番明るい色の光。左右対称にそろえる。
- 背景タイルは 32×32（ゲーム上 2×2 マス分の模様）で、上下左右につないで継ぎ目が出ないこと。奥の壁・柱は暗い 2 色だけ、乗れる壁・足場は明るい色が主体（前回までと同じ）。

## 4. スクリプトの修正

- `tools/sprite_prompts.json`：サイズを上の表に合わせる。各スプライトに `"scale": 2` を持たせる。
- `tools/gen_sprites.py`：`overrides.json` に `{ "w": ..., "scale": 2 }` の形で書く。`renderScale` は 2 のまま残す。サイズの検査も新しいサイズで行う。
- `tools/polish_sprites.py`：32×32 でも動くようにする（`FRAME_W` を新しい幅に。縁取りは 1px のままでよい）。
- `assets/preview/compare.png`：作業前（16×16）と作業後（32×32）を、**ゲーム上の同じ大きさ**（前は 16 倍、後は 8 倍に拡大）で並べる。
- `sw.js` の `VERSION` を上げる。

## 5. 完成の条件（チェックリスト）

- [ ] 表のスプライトがすべて新しいサイズ・コマ数で、4色と透明だけ
- [ ] `overrides.json` が `{ "w": ..., "scale": 2 }` の形になり、`renderScale` が 2
- [ ] ゲームを起動すると、主人公・敵・背景が細かく描かれている（ぼやけていない）
- [ ] 主人公で、目のハイライト・アホ毛・編み込み・丸い肩当て・剣が見て分かる
- [ ] 歩き4コマで頭が同じ（チラつかない）
- [ ] 主人公の足が床に立ち、当たり判定と見た目がずれていない。攻撃の剣先が右端に届く
- [ ] 背景タイルを並べて継ぎ目が出ない
- [ ] `P` キーのパレット切り替えで、新しい絵の色も変わる
- [ ] スタートからボスを倒してクリアまで、エラーなく遊べる
- [ ] スマホ（縦・横）で表示が崩れない
- [ ] API キーをコミットしていない。作業はブランチに push して PR を作る

## 6. やらないこと

- ゲームの計算の解像度（160×144）、当たり判定、ステージの地図、ゲームの動きは変えない。
- 既存のゲーム（キャッスルヴァニアなど）の名前・キャラクター・絵に似せない。
