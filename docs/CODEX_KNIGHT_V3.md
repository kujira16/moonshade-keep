# Codex への指示書（第3弾）：16×16 でも「あの騎士だ」と分かる主人公にする

前回（`docs/CODEX_SPRITES_HQ.md`）で、線のかすれやコマごとのブレは直りました。
でも、まだ**何のキャラクターか分からない**。今回はこれを直すのが目的です。
共通のルール（API キーの扱い、`overrides.json`、`sw.js`、`polish_sprites.py` を通す流れ、候補を作って採点する仕組み）は前回までと同じです。

- 参照画像：`docs/reference/knight.png`（金髪の騎士の女の子）
- **目標の配置図（新規）**：`docs/reference/knight_16_template.png`（16×16）、拡大版 `docs/reference/knight_16_template_x16.png`

---

## 0. 分からない原因（調べた結果）

今の `assets/source/player_idle.png` を1ドットずつ見ると、こうなっている。

```
................
........111.....     ← アホ毛のつもりが、髪のかたまりに埋もれている
......44111.....
....11122111....     ← 髪(1)と顔(2)がほぼ同じ明るさで、境目がない
...1122111114...
...4211111414...     ← 目が1ドットあるが、顔と髪の区別がないので目に見えない
...422211111....
...42222222.....
...444444424....     ← 胴体の大半が一番暗い色。銀の鎧が消えている
....44422244....
....44444444....
...4444444444...
....4133313.....
```

原因は4つ。

1. **パレットの明るい2色がほぼ同じ色。** 今の緑（`#9bbc0f` と `#8bac0f`）は見分けがつかないので、「金髪」と「顔」と「銀の鎧」が全部同じに見える。実質3色しか使えていない。
2. **最初から4色の緑で描かせている。** gpt-image に緑4色で描かせると、「黄色い髪」「肌」「銀」「青」という**部位の違いが、生成の段階で失われる**。あとから部位ごとに色を割り当て直すことができない。
3. **gpt-image に 16×16 のマス目をきっちり描かせるのは無理がある。** マスが細かすぎて、アホ毛や目のような 1〜2 ドットの特徴が、毎回ずれたり消えたりする。
4. **「どのドットが何か」の目標がない。** 採点が明るさや大きさだけなので、騎士らしくなくても高得点になる。

---

## 1. やること

### 1-1. パレットをコントラストの高い4色に変える（ゲーム側）

ゲームボーイ風のまま、4色の明るさの差がはっきりした色に変える。

| 番号 | 新しい色 | 今の色 | 用途 |
|---|---|---|---|
| 1 | `#e0f8d0` | `#9bbc0f` | 一番明るい：金髪、アホ毛、光 |
| 2 | `#88c070` | `#8bac0f` | 明るい：顔、銀の鎧、すね当て |
| 3 | `#346856` | `#306230` | 暗い：青い服、鞘、奥の壁 |
| 4 | `#081820` | `#0f380f` | 一番暗い：輪郭、目、ベルト、ブーツ |

変更する場所：
- `js/sprites.js` の `PALETTES.green` を新しい4色にする（名前は `green` のまま。`P` キーの切り替えはそのまま動くこと）。
- `js/sprites.js` の `greenShades`（PNG の色を番号に戻す表）が、**新しい4色と古い4色の両方**を認識するようにする。
- `index.html` の `theme-color` と CSS の色、`manifest.webmanifest` の色、`tools/make_icons.py` の色も新しい4色に合わせる（アイコンは作り直す）。
- `tools/polish_sprites.py` と `tools/sprite_grid.py` の色の定義を新しい4色にする。**既存の PNG（古い緑）も読めるように**、読み込み時は古い4色も番号に変換する。
- 背景（夜空・城のシルエット・月）は `game.js` がパレット番号で描いているので、そのままで新しい色になる。見た目を確認すること。

### 1-2. gpt-image には「フルカラーの 32×32 ドット絵」を描かせる

16×16・4色で直接描かせるのをやめ、次の流れにする（主人公の5種類が対象。敵・背景は 1-5 を参照）。

```
gpt-image（images.edit、参照に knight.png）
  → フルカラーの 32×32 ドット絵（1024×1024、1 マス = 32px）
  → マス目読み取り（前回の sprite_grid.py の方式を 32×32 で）
  → 色相で部位を判定（下の表）→ 32×32 の「部位マップ」
  → 部位の優先順位つきで 16×16 に縮小 → 16×16 の部位マップ
  → 部位 → パレット番号 に置き換え → assets/source/<名前>.png
  → polish_sprites.py → assets/<名前>.png
```

プロンプト（英語、前半は全ポーズ共通）：

```
Full-color pixel art sprite of this exact character, on a strict 32x32
pixel grid: every grid cell is one solid square of a single color,
all cells the same size, perfectly aligned, filling the whole image.
Limited palette: blonde yellow hair, light skin, silver-white armor,
royal blue tunic, brown belt, dark navy outline, black eyes.
Chibi proportions: head is about half of the body height.
Side view facing right. Clear 1-pixel dark outline around everything.
No anti-aliasing, no gradients, no dithering, no texture inside cells,
transparent background, no text, no border.
Must be clearly visible: one upright hair strand (ahoge) on top of the
head, big blonde hair mass, a big eye, round silver shoulder guards,
silver chest plate, blue tunic below the chest plate, brown belt,
sword with blue scabbard behind the hip, silver shin guards.
```

ポーズごとの後半は前回と同じ（立ち・歩き4コマ・ジャンプ・地上攻撃・空中攻撃）。歩き4コマは、**1536×1024 に 4 コマ横並び（128×32 のマス、1 マス = 12px）** で1枚にまとめるか、**立ちの採用画像を参照にして 1 コマずつ 1024×1024 で作る**かを試し、採点が高いほうを採用する。

### 1-3. 色相で部位を判定する

32×32 に読み取った各マスの色（RGB）を HSV にして、次の表で部位を決める。しきい値は `tools/sprite_prompts.json` に書いて調整できるようにする。

| 部位 | 記号 | 判定の目安 | パレット番号 |
|---|---|---|---|
| 輪郭 | O | 明度が低い（V < 0.25） | 4 |
| 目 | E | 顔の範囲内の、黒〜濃い青 | 4 |
| 金髪・アホ毛 | H / A | 黄〜橙（H 35〜60°）で彩度・明度が高い。アホ毛は頭の一番上に飛び出した部分 | 1 |
| 顔（肌） | F | 肌色（H 15〜40°、彩度が低め、明度が高い） | 2 |
| 銀の鎧 | P / C / L | 彩度が低く明度が高い（S < 0.2、V > 0.6）。位置で肩当て P・胸当て C・すね当て L に分ける | 2（一番明るいハイライトは 1） |
| 青い服 | T | 青（H 200〜250°） | 3 |
| 鞘 | S | 青で、体の外に細長く出ている部分 | 3 |
| ベルト | B | 茶色（H 15〜40°、明度が低め） | 4 |
| ブーツ | K | 足元の暗い部分 | 4 |

### 1-4. 部位の優先順位つきで 16×16 に縮小する

32×32 → 16×16 は、2×2 のマスを 1 ドットにまとめる。平均や多数決ではなく、**次の優先順位で一番上にある部位を残す**。こうすると、目やアホ毛のような 1 ドットの特徴が消えない。

```
目 E > アホ毛 A > ベルト B > 輪郭 O > 顔 F > 肩当て P > 金髪 H > 胸当て C > 服 T > 鞘 S > すね当て L > ブーツ K > 透明
```

ただし輪郭 O が優先されすぎて全体が黒くなる場合は、「2×2 の中に輪郭以外が 3 マス以上あれば輪郭にしない」ルールを入れる。

### 1-5. 目標の配置図と比べて採点する

`docs/reference/knight_16_template.png` は、16×16 で「あの騎士だ」と分かるように、私が部位の配置を1ドットずつ決めた**目標の図**です。部位で書くとこうなる。

```
.........OO.....    A = アホ毛
........OAO.....    H = 金髪
.....OOOOHOOO...    F = 顔
....OHHHHHHHHO..    E = 目（縦2ドット）
...OHHHHHHHHHHO.    P = 肩当て
...OHHHHHOFFFFO.    C = 胸当て
...OHHHHOFFEFFO.    T = 青い服
...OHHHHOFFEFO..    B = ベルト
...OHHOOOFFFFO..    S = 鞘（体の後ろに斜め）
....OHO.OOOOO...    L = すね当て
...OPPOCCCCPPO..    K = ブーツ
..OPPPOCCCCPPPO.    O = 輪郭
..OOOOTBBBBTOO..
..S.OTTTTTTO....
.S..OLLOOLLO....
S...OKKO.OKKO...
```

- この図を部位マップとして読み込み、**候補ごとに「部位が一致しているドットの割合」**を出して採点に加える（重み大）。特に **アホ毛・目・髪と顔の境目・肩当て** の位置が合っているかを重く見る。
- この図は「目標」であって正解ではない。生成画像のほうが良い形（髪の流れ、鎧の形など）なら、そちらを優先してよい。ただし次の **必須条件** は、どの候補でも必ず満たすように、満たさない場合は最後に自動で直す。
  1. 頭のてっぺんにアホ毛（一番明るい色が 1〜2 ドット、周りが輪郭）
  2. 髪（一番明るい）と顔（明るい）の間に輪郭か色の境目がある
  3. 目が一番暗い色で 1〜2 ドット、顔の右寄り
  4. 胸から肩に明るい色（鎧）があり、その下に暗い色（服）がある
  5. 一番暗い色の輪郭が全体を囲んでいる
- 全候補の採点結果と、目標の図・候補・最終結果を並べた `assets/preview/knight_v3.png`（8倍）を作る。

### 1-6. 敵・ボス・アイテム・背景

- 今の絵を作り直す必要はない。新しいパレットに合わせて、**明るい2色がはっきり分かれて見えるか**だけ確認し、つぶれているものだけ作り直す。
- 作り直す場合も、主人公と同じく「フルカラーで生成 → 色相で部位判定 → 番号に置き換え」の流れを使うと良い（例：ガイコツは骨＝1、影＝2、目の穴＝4）。

## 2. 完成の条件（チェックリスト）

- [ ] パレットが新しい4色になり、ゲーム・アイコン・ページの色がそろっている。`P` キーの切り替えも動く
- [ ] 古い緑で保存された PNG も、正しい番号で読み込まれる
- [ ] 主人公の 16×16 で、**アホ毛・金髪・顔と目・銀の鎧・青い服**が見て分かる（`assets/preview/knight_v3.png` で確認）
- [ ] 必須条件 1〜5 をすべての主人公スプライト（立ち・歩き4コマ・ジャンプ・攻撃2種）が満たす
- [ ] 歩き4コマで頭が同じ（チラつかない）
- [ ] 攻撃コマで剣先が 15 列目、8 行目あたりに届く
- [ ] `gen_sprites.py --reprocess` で、API を呼ばずに作り直せる
- [ ] `sw.js` の `VERSION` を上げた
- [ ] スタートからボスを倒してクリアまで、エラーなく遊べる
- [ ] API キーをコミットしていない
- [ ] 作業はブランチに push して PR を作る（main に直接 push しない）

## 3. やらないこと

- 16×16 のサイズ、当たり判定、ステージの地図、ゲームの動きは変えない。
- 既存のゲーム（キャッスルヴァニアなど）の名前・キャラクター・絵に似せない。
